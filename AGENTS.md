# Инструкции для агентов Sabacc

Sabacc — браузерная игра Kessel Sabacc для двух игроков. Отвечай и веди документацию
на русском; имена кода, веток и технические идентификаторы оставляй на английском.

## Начало работы

### Всегда

1. Выполни `git status --short --branch`; сохрани существующие изменения пользователя.
2. Прочитай [контекст проекта](docs/agents/project-context.md).
3. Примени правила [Git](docs/agents/rules/git.md), [Jira и PR](docs/agents/rules/tickets.md),
   [changelog](docs/agents/rules/changelog.md).
4. Для затронутой стороны прочитай [frontend/AGENTS.md](frontend/AGENTS.md)
   и/или [backend/AGENTS.md](backend/AGENTS.md).

### По задаче

5. Изучи тикет и критерии приёмки.
6. При продуктовом изменении найди затронутые места в коде и в
   [Project.md](Project.md) / [Bugs.md](Bugs.md); документы могут отставать от кода.
7. При локальном запуске стенда — [local-setup](docs/how-to/local-setup.md).
   Карта документации и README: [docs/README.md](docs/README.md), [README](README.md).

### При сдаче

8. Сверь критерии [CONTRIBUTING.md](CONTRIBUTING.md) и выполни затронутые проверки
   из [verification.md](docs/agents/verification.md).
9. Проверь diff, отсутствие секретов и лишних артефактов.

## Работа и завершение

- Делай минимальное законченное изменение по задаче; не исправляй весь каталог багов попутно.
- Реальное поведение проверяй по коду; требуемое — по задаче и согласованным требованиям.
  Существенное противоречие проясни до зависимого изменения.
- При изменении REST/STOMP проверяй сервер, клиентские типы и обработчики вместе.
- Локальный стенд: `./scripts/dev.sh up`; только сборка: `./scripts/dev.sh build`.
  Эти команды не заменяют тесты.
- Команды и ограничения проверок: [verification.md](docs/agents/verification.md).
- Для бага воспроизведи проблему и добавь осмысленную регрессионную проверку,
  когда это возможно. Не называй закомментированные тесты работающими.
- Обнови документацию и `changelog.md`, если изменение этого требует.
- В результате сообщи: что изменено, какие проверки выполнены, что не проверено и почему.
  Не заявляй об успешной сборке, публикации PR или смене статуса без подтверждения.

## Границы

- `.env`, токены Jira/GitHub, пароли и локальные данные БД не коммить и не выводи в логи.
- Не удаляй `postgres-data/`, не запускай очистку пользовательской БД для проверки задачи.
- Не выполняй deploy, merge, push или изменения Jira без поручения, которое их включает.
  Уже данное разрешение повторно не запрашивай.
- Ссылки старой команды в `Project.md` — исторические сведения, не адреса текущего проекта.
- Общие правила хранятся в `docs/agents/rules/`; `.cursor/rules/` только подключает их.
