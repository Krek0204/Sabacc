# Backend

Применяются также корневой [AGENTS.md](../AGENTS.md) и общие правила.

- Используй JDK 21 и Gradle wrapper; не мигрируй стек и не обновляй зависимости попутно.
- Java содержит HTTP/STOMP, сервисы и persistence; Kotlin `gamecore` — игровую логику.
  Сохраняй границы через `IGameSession`, `IGameSessionFactory`, `IGameMessageExchanger`.
- Проверяй обе стороны REST/STOMP-контракта: DTO, enum, destinations и клиентские handlers.
- Не считай `playerId` из тела сообщения доказательством права действовать от имени игрока.
  При работе с состоянием учитывай приватность рук, допустимость хода и повторные сообщения.
- Изменяя переходы сессии, проверяй отключение/возврат обоих игроков, завершение,
  очистку in-memory состояния и согласованность комнаты в БД.
- Изменения схемы оформляй новой Flyway-миграцией. Не редактируй уже применённые миграции
  и не обходи `ddl-auto: validate` автоматическим созданием схемы.
- Следуй существующей модели исключений и событий; не скрывай ошибку пустым catch.
- Из `backend/`: `./gradlew test`, `./gradlew build`. Нужны настроенные профиль и БД;
  подробности в [verification.md](../docs/agents/verification.md).
- `GameSessionTest.kt` сейчас закомментирован. При исправлении ядра добавь исполняемую
  проверку затронутого поведения; не считай существующий файл покрытием.
- Dockerfile собирает `bootJar` через Gradle wrapper; это не замена запуску тестов.
