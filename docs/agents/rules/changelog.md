# Ведение changelog.md

- Единственный журнал изменений — [changelog.md](../../../changelog.md) в корне.
- В ходе задачи добавляй запись в `## [Unreleased]` в том же PR, что и изменение.
- Категории: `Added`, `Changed`, `Fixed`, `Removed`, `Security`.
  Создавай только непустые категории; одну запись не дублируй между ними.
- Запись коротко объясняет эффект для игрока, разработчика или оператора.
  Не копируй перечень файлов и историю коммитов.
- Добавляй ссылку на реальную Jira-задачу, если она есть:
  `- Исправлен выбор кубика со значением 1 ([SCRUM-123](https://isa-sabacc.atlassian.net/browse/SCRUM-123)).`
  Это пример формата, а не выполненное исправление.
- Без тикета допустима запись без ссылки; причину отсутствия тикета укажи в PR.
- Запись нужна для поведения игры, API/STOMP, конфигурации/запуска, безопасности,
  совместимости и существенных изменений процесса разработки, включая этот harness.
- Опечатки в документации, тесты без изменения поведения и внутренний рефакторинг
  без внешнего эффекта могут обходиться без записи; кратко объясни это в PR.
- Не записывай планы как сделанные изменения; незавершённость обозначай явно.
- При отдельно порученном релизе перенеси выпущенные записи в
  `## [<version>] - YYYY-MM-DD`, оставь `Unreleased` для следующих изменений.
  Версию бери из согласованного релиза/tag, дату — фактическую дату выпуска.
- Не назначай релизную версию по старым учебным материалам или package.json автоматически.
  Не восстанавливай вымышленную историю и не переписывай записи выпущенных версий
  кроме исправления фактических ошибок.
- При конфликте слияния сохрани записи обеих задач, убери лишь реальные дубли.
