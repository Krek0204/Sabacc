# Диагностика локального стенда

Все команды ниже выполняются из корня для полного Compose. Логи могут содержать
пользовательские данные: перед добавлением в тикет оставляй только нужный фрагмент.

## Страница не открывается или Nginx отвечает 502

```sh
docker compose --env-file .env ps -a
docker compose --env-file .env logs --tail=100 nginx backend postgres
```

Проверь свободный порт 80, наличие `frontend/dist/index.html`, готовность БД и backend.
Frontend-контейнер с кодом 0 не обслуживает HTTP и сам по себе не является ошибкой.
Compose не ждёт healthcheck PostgreSQL перед стартом backend; по логам отдели
ещё не готовую БД от неправильных реквизитов или ошибки приложения.

## Ошибка БД или конфликт контейнеров

Не запускай одновременно полный и DB-only Compose. Для переключения останови
предыдущий стек через соответствующий `down`, сохрани каталог данных.
Хост БД внутри Compose — `postgres`, при запуске backend на машине — `localhost`.
Изменение POSTGRES_PASSWORD не перенастраивает существующий `postgres-data`;
не удаляй базу для обхода ошибки, сначала проверь реквизиты и ценность данных.

## Spring не стартует без Docker

Gradle не читает корневой `.env`. Проверь `CRON_USER_CLEANUP`, datasource и профиль.
Полные настройки STOMP находятся в `application-prod.yml`; базовому профилю их не хватает.
Пример окружения приведён в [local-setup.md](local-setup.md).
Не подменяй серверные настройки секретами в отслеживаемом YAML.

## В Vite интерфейс есть, API или игра не работают

В `frontend/vite.config.ts` rewrite удаляет `/api`, хотя REST сервера начинается
с `/api/v1`. Клиентский `useWebSocketGame` использует `/game`, а proxy описывает
только `/api` и `/ws`. Это известные несогласованности исходной конфигурации.
Проверь реальный URL в Network браузера; наличие страницы на 5173 не доказывает работу игры.
Исправление маршрутизации выполняй отдельной задачей и проверяй REST и SockJS вместе.

## Сборка проходит, но поведение не проверено

Dockerfile backend выполняет `./gradlew bootJar --no-daemon`, без запуска тестов. `GameSessionTest.kt` закомментирован.
Spring context test требует окружения, а существующие frontend-тесты не покрывают партию.
Используй [команды и ручной сценарий](../agents/verification.md), указывая реальные результаты.

## Изменение .env не влияет на приложение

Различай конфигурацию Compose, Spring и время сборки frontend.
Статика требует пересборки. PUBLIC_IP не связан с origins в текущем YAML,
а профиль prod зафиксирован непосредственно в Compose.
Подробности — в [инструкции запуска](local-setup.md).
