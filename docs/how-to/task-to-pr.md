# Как провести задачу от Jira до PR

## 1. Подготовь задачу

Используй проект SCRUM. Шаблон содержимого тикета:

```text
Цель / проблема:
Текущее поведение:
Ожидаемый результат:
Объём работы и ограничения:
Критерии приёмки:
Шаги воспроизведения (для бага):
Способ проверки:
Зависимости / открытые вопросы:
```

Не все поля нужны каждой задаче. Проверяемые критерии и способ проверки нужны всегда.
Для пунктов Bugs.md добавляй ссылку/идентификатор исходного дефекта, но не считай его Jira-ключом.

## 2. Создай ветку

Проверь рабочее дерево, обнови origin/main и создай ветку с реальным ключом задачи.
Точные форматы и исключение без тикета — в [правилах Git](../agents/rules/git.md).
Не копируй номер из примера как номер новой задачи.

## 3. Реализуй и проверь

Прочитай соответствующие AGENTS.md и код, сопоставь критерии с местами изменений.
Выполни [проверки](../agents/verification.md), проверь diff и артефакты.
Обнови документацию и [changelog](../agents/rules/changelog.md).
Если появилась независимая проблема, отдели её от текущего объёма.

## 4. Подготовь ревью

При наличии поручения на публикацию отправь ветку в GitHub и открой PR в main.
Заголовок строго в формате `SCRUM-24 Исправить …` — см. [правила Jira/PR](../agents/rules/tickets.md).
Используй [шаблон](../../.github/pull_request_template.md): ссылка на Jira,
результат, доказательства проверок и ограничения. Назначь другого участника reviewer.
Если работа не закончена, явно обозначь это и оставь PR в draft.

## 5. Заверши

Ответь на замечания и повтори затронутые проверки после исправлений.
Перед merge выполни [критерии готовности](../../CONTRIBUTING.md).
Merge и смена статуса Jira выполняются в рамках прав и поручения;
названия переходов проверь в реальном workflow. Ссылка на PR не закрывает Jira автоматически.
В результате зафиксируй, что слито, что проверено и требуется ли отдельная выкладка.
