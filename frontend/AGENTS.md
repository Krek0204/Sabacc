# Frontend

Применяются также корневой [AGENTS.md](../AGENTS.md) и общие правила.

- Сохраняй существующие слои `app`, `pages`, `widgets`, `features`, `entities`, `shared`.
  Переиспользуй публичные `index.ts`, общие UI и alias `@`; не затевай перестройку слоёв попутно.
- Используй TypeScript и функциональные React-компоненты; соблюдай порядок и
  безусловность вызова hooks. Следуй стилю соседнего кода и `.editorconfig`.
- HTTP проходит через RTK Query (`shared/api/rtkApi.ts`), игровое состояние —
  через STOMP-хуки и `features/Game/model`; не создавай второй источник истины без причины.
- Подписки/соединения должны иметь cleanup. Проверяй повторное подключение,
  обновление страницы, события для обоих игроков и отсутствие повторной обработки.
- UI не определяет допустимость серверного хода. Не удаляй ресурс окончательно
  до подтверждения сервера без корректного отката при отказе.
- При смене DTO/типов событий сверяй backend; не добавляй неподтверждённые поля.
- Не переименовывай существующий маршрут `/rools` без учёта ссылок и задачи.
- Из `frontend/`: `npm ci`, `npm run lint`, `npm run test -- --run`, `npm run build`.
  Lint на существующем коде красный: зелёный lint не критерий готовности вне lint-задач;
  не чини массу замечаний попутно. Ограничения и ручной сценарий:
  [verification.md](../docs/agents/verification.md).
- При изменении зависимостей обновляй `package.json` и `package-lock.json` согласованно.
  `npm ci` предназначен для установки по существующему lock-файлу.
